Quarkus JS Client Generation

Auto-generated typed JavaScript clients for REST, GraphQL, and JSON-RPC

Import maps + Web Dependency Locator + build-time code generation

The Problem

Calling backend APIs from JavaScript requires a lot of manual wiring

Different protocols, different patterns, easy to get wrong

REST without generation

1. Know the URL path: /api/tasks/{id}
2. Know the HTTP method: GET / POST / PUT / DELETE
3. Set headers: Content-Type, Accept, Authorization
4. Build request body: JSON.stringify({title: '...'})
5. Handle path params: replace {id} manually
6. Handle query params: build URLSearchParams
7. Parse response: await resp.json()
8. Handle errors: check resp.ok, parse error body
// What you write today
const resp = await fetch('/api/tasks', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json',
               'Accept': 'application/json' },
    body: JSON.stringify({ title: 'My task' })
});
if (!resp.ok) throw new Error(resp.statusText);
const task = await resp.json();

GraphQL without generation

1. Write the query string: query { tasks { id title completed } }
2. Know the schema types: String, BigInteger, [Task]
3. Declare variables: $title: String!
4. Build selection set: which fields to return?
5. POST to endpoint: { query: '...', variables: {...} }
6. Unwrap response: response.data.tasks
7. Handle errors array: response.errors[].message
8. Subscriptions: implement graphql-transport-ws protocol
// What you write today
const resp = await fetch('/graphql', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
        query: `mutation addTask($title: String) {
            addTask(title: $title) { id title completed }
        }`,
        variables: { title: 'My task' }
    })
});
const { data, errors } = await resp.json();
if (errors) throw new Error(errors[0].message);

JSON-RPC without generation

1. Open WebSocket: new WebSocket(url)
2. Implement JSON-RPC 2.0: { jsonrpc: "2.0", method, params, id }
3. Track request IDs: match responses to requests
4. Handle errors: { code: -32000, message: '...' }
5. Subscriptions: track subscription IDs
6. Notifications: method: "subscription" messages
7. Reconnection: exponential backoff logic
8. Auth: Sec-WebSocket-Protocol encoding
// What you write today
const ws = new WebSocket('ws://localhost:8080/quarkus/json-rpc');
let id = 0;
const pending = new Map();
ws.onmessage = (e) => {
    const msg = JSON.parse(e.data);
    if (msg.id && pending.has(msg.id)) {
        pending.get(msg.id).resolve(msg.result);
        pending.delete(msg.id);
    }
};
function call(method, params) {
    return new Promise((resolve, reject) => {
        const reqId = ++id;
        pending.set(reqId, { resolve, reject });
        ws.send(JSON.stringify({ jsonrpc: '2.0', method, params, id: reqId }));
    });
}

The Solution

Enable one config property. Get a typed JS client.

# application.properties
quarkus.smallrye-openapi.js-client.enabled=true
quarkus.smallrye-graphql.js-client.enabled=true
quarkus.json-rpc.js-client.enabled=true

The extension scans your endpoints at build time and generates typed JavaScript modules,
served via import maps through Web Dependency Locator

How It Works

Build Time:
  Java endpoints → scan annotations / schema
    → generate graphql-client.js / rest-client.js / jsonrpc-client.js
    → generate typed proxy (graphql-api.js / rest-api.js / jsonrpc-api.js)
    → produce WebDependencyJarBuildItem with import mappings

Runtime:
  HTML page loads → {#bundle /} injects importmap script
  Browser resolves @quarkus/rest-api → /_static/quarkus-rest-api/rest-api.js
  Your code: import { TaskResource } from '@quarkus/rest-api'

REST with generation

Server (Java)
@Path("/api/tasks")
public class TaskResource {

    @GET
    public List<Task> list() {
        return taskService.getAllTasks();
    }

    @POST
    public Task create(Task task) {
        return taskService.addTask(task.getTitle());
    }

    @DELETE
    @Path("/{id}")
    public boolean delete(@PathParam("id") long id) {
        return taskService.deleteTask(id);
    }
}
Client (JavaScript)
import { TaskResource }
    from '@quarkus/rest-api';

// List tasks
const tasks = await TaskResource
    .getApiTasks();

// Create a task
const task = await TaskResource
    .postApiTasks({ title: 'New task' });

// Delete a task
await TaskResource
    .deleteApiTasksId({ id: 42 });

GraphQL with generation

Server (Java)
@GraphQLApi
public class TaskGraphQL {

    @Query
    public List<Task> tasks() {
        return taskService.getAllTasks();
    }

    @Mutation
    public Task addTask(String title) {
        return taskService.addTask(title);
    }

    @Mutation
    public boolean deleteTask(long id) {
        return taskService.deleteTask(id);
    }
}
Client (JavaScript)
import { Queries, Mutations }
    from '@quarkus/graphql-api';

// Query tasks
const data = await Queries.tasks();
const tasks = data.tasks;

// Mutate - add a task
const result = await Mutations
    .addTask({ title: 'New task' });

// Mutate - delete a task
await Mutations
    .deleteTask({ id: 42 });

Security

All three clients support token and tokenProvider

import { RestClient } from '@quarkus/rest';
import { GraphQLClient } from '@quarkus/graphql';
import { JsonRPCClient } from '@quarkiverse/json-rpc';

// Static token
RestClient.configure({ token: 'Bearer my-jwt' });

// Dynamic token (e.g. with Keycloak)
GraphQLClient.configure({
    tokenProvider: async () => {
        await keycloak.updateToken(30);
        return 'Bearer ' + keycloak.token;
    }
});

// Works the same for all three
JsonRPCClient.configure({ token: 'Bearer my-jwt' });
